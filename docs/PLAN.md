# Aquarium — 技术方案

## 1. 目标

一个网页端、可交互、超写实风格的金鱼水族箱。核心不变量：

1. **看起来像真的** —— 优先保证光影（焦散、体积光、玻璃折射、水下吸收）和动态细节（摆尾、鱼鳍抖动、气泡、浮尘、水面涟漪）。
2. **能玩** —— 鼠标能吸引/惊扰鱼，点击投喂，鱼会抢食、吃饱后变懒。
3. **能跑** —— 1080p 下目标 60fps（独显），30fps 以上（核显），提供画质档位。

不做：多人、存档、物理引擎、外部 3D 模型/贴图资源（全部程序化生成，仓库零资产依赖）。

## 2. 技术栈

| 项 | 选择 | 理由 |
|---|---|---|
| 渲染 | Three.js r16x + 自写 GLSL | 成熟的 RT/composer 管线，水体着色器必须手写 |
| 语言 | TypeScript | 着色器参数多，类型能救命 |
| 构建 | Vite | 秒级热更新 |
| 状态/UI | 原生 DOM + 少量 CSS | 只有几行 HUD，不上框架 |
| 部署 | GitHub Pages（Actions） | 静态站点 |

目标浏览器：Chrome/Edge/Firefox 最新版，WebGL2 必需。
不使用任何 skill/插件脚手架，所有代码手写。

## 3. 场景构成

```
Camera (轨道，位于缸外)
└─ Tank (玻璃箱 8 × 4.5 × 4，壁厚 0.08)
   ├─ WaterVolume (水下介质：雾 + 吸收)
   ├─ Surface (水面，动态法线 + 涟漪)
   ├─ SandBed (噪声起伏沙床 + 程序化石子/沉木/水草)
   ├─ Fish ×7 (程序化几何 + 自定义着色器)
   ├─ Food (投喂颗粒)
   ├─ Particles (浮尘) / Bubbles (气泡)
   └─ Lights (顶灯 + 侧向补光 + 环境贴图)
```

## 4. 渲染管线

每帧顺序：

```
1. 更新仿真 (鱼行为 / 食物 / 粒子 / 水面高度场)
2. PMREM 程序化环境贴图 (仅初始化一次)
3. 渲染不透明场景 (水草、鱼身、沙床、沉木) → sceneRT (HDR, RGBA16F, MSAA×4)
4. 渲染水中介质：全屏 pass，读 sceneRT + depth
     - 深度吸收 (Beer-Lambert，分通道)
     - 光线散射 (与太阳方向相关的内散射)
     - 焦散叠乘到沙床与物体表面 (由第 6 步材质直接采样)
5. 渲染半透明：鱼鳍、气泡、浮尘、食物 (back-to-front 排序)
6. 后处理链：
   GodRays(RadialBlur 光源遮罩) → Bloom(自定义 mip 链) → DOF(轻微，焦点跟随最近鱼)
   → ACES ToneMapping → 色差 + 颗粒 + 暗角 → 输出
7. 玻璃面板最后叠加：读 sceneRT 做折射偏移 + 吸收染色 + 菲涅尔反射 + 边缘高光
```

关键实现要点：

- **焦散**：使用迭代 sin 折叠的经典 tileable caustic 算法（David Hoskins 风格），两层不同速度/尺度的叠加，按世界坐标投影到沙床和鱼背，强度随离水面深度衰减、随水面涟漪法线扰动。仅在材质里 sample 一张程序化生成的 512² 焦散图（每帧或每 2 帧更新一次，`RT` 复用），避免每个材质重复算。
- **体积光柱**：顶灯在玻璃中投下的光柱用径向模糊遮罩 pass，配合水下雾的内散射，形成从水面斜射下来的丁达尔效应。
- **玻璃**：不做 MeshPhysicalMaterial 的 transmission（太贵且排序差），改为最后叠加的 quad 面板，采样 sceneRT 时按法线做 UV 偏移（IOR 1.5，壁厚参与偏移量），叠加 `pow(fresnel, 4)` 的反射与立方体内壁高光；缸口做一条更亮的斜切边，这是玻璃感的来源。
- **吸收配色**：`σ = (0.55, 0.16, 0.09) / 缸长`，红光先消失，远端的物体天然偏青，无需美术调色。
- **鱼**：程序化网格（脊线 64 段 × 截面 16 点），顶点着色器按 `t`（沿体轴）做行波摆动 `sin(k*t - ω*t)`，振幅从 0 线性增至尾部 1.0；鳍是单独的双面半透明网格，用顶点噪声做抖动。
- **鱼材质**：分层——基色（背橙腹白渐变）+ 程序化鳞片（六边形/菱形单元，法线扰动 + 高光遮罩）+ 薄膜虹彩（Fresnel 驱动的色相偏移）+ SSS 近似（wrap diffuse）。
- **水面**：顶点高度 = 基础波浪 + 最多 8 个投喂涟漪（GPU 传 uniform 数组），法线实时求导，用于折射、焦散强度和相机看到的水下变形。
- **气泡**：InstancedMesh 广告牌，上升时做正弦摆动 + 椭圆形变，采样 sceneRT 做边缘折射。
- **浮尘**：InstancedMesh 小球，软深度衰减，靠 curl noise 缓慢漂浮。

## 5. 玩法与交互

- **相机**：OrbitControls（限制俯仰、距离），阻尼；闲置 5s 后自动缓慢巡游。
- **鼠标移动**：射线打到玻璃/水中平面 → 得到 3D 兴趣点。鱼在 3 单位内会好奇转向、减速、侧身盯着点；快速挥动鼠标（速度阈值）则视为惊吓，鱼群散开 1.5s。
- **点击**：在射线与水面的交点撒下 3–5 颗鱼食，伴随涟漪。食物缓慢下沉（带阻尼与横向摇摆），60s 未吃则沉底消失。
- **吃食**：食物半径 0.25 内触发吞食动画（头部轻点、食物消失、饱和度 +）。鱼按饥饿度排序抢食。
- **状态**：`hunger ∈ [0,1]`，每分钟 +0.25。`hunger < 0.2` 时游速降低、尾频变慢、更爱在底部悬停（"吃饱了"可被看出来）。
- **HUD**：左上角操作提示（10s 后淡出）、右下角画质切换（高/中/低）、右上角鱼食计数。全部原生 DOM。

## 7. 里程碑

| 阶段 | 内容 | 完成标志 |
|---|---|---|
| **M0** 骨架 | Vite + Three 初始化、玻璃箱、沙床、相机、灯光、部署流水线 | 能打开页面看到空缸并能环绕 |
| **M1** 水体 | 焦散、水下吸收、内散射、光柱、水面折射 | 静止画面已有"水下感" |
| **M2** 鱼 | 程序化鱼身 + 鳞片材质 + 摆尾 + 鱼鳍 + 游动路径 | 一条鱼在缸里自然地游 |
| **M3** 生态 | 7 条鱼、群游避墙、好奇/惊吓、投喂与抢食、气泡、浮尘 | 交互闭环，可以玩 |
| **M4** 打磨 | 后处理（Bloom/DOF/颗粒）、玻璃菲涅尔、色调映射、涟漪联动焦散 | 截图级静帧 |
| **M5** 收尾 | 画质档位、性能剖析、README 与在线 Demo、可访问性 | 1080p 60fps，线上可玩 |

每个里程碑独立可运行、可提交。优先保证 M1+M2 的视觉质量，因为这是项目成败所在。

## 8. 性能预算（高画质，1080p，60fps）

- Draw call < 60（鱼合并同一材质，水草/石子用 InstancedMesh）
- 主 pass 三角面 < 250k
- 全屏 pass 数量 ≤ 6
- 焦散 RT 512²、每 2 帧更新
- 后处理 Bloom 6 mip；DOF 降采样 1/2
- 低画质档：关 DOF、关光柱、焦散分辨率减半、粒子数减 70%

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 程序化鱼"塑料感" | 先做静帧对比；鳞片法线 + SSS + 虹彩三层叠加，必要时加细微脏污/色斑 |
| 半透明排序穿帮 | 鱼鳍/气泡统一用深度预 pass 后的排序绘制，关 depthWrite |
| 焦散开销 | 独立 RT，按需更新频率，低配降分辨率 |
| 移动端性能 | 明确不支持触屏高画质；提供中/低档并降低 DPR（上限 1.5） |
| 折射与 UI 射线不一致 | 交互用理想平面求交，视觉偏差靠 IOR 偏移补偿，肉眼不可辨 |

## 10. 验收标准

1. 静帧截图（默认机位）具备：可见焦散、光柱、玻璃菲涅尔、鱼鳞高光、半透明鱼鳍。
2. 鼠标移动时鱼会转向跟随；快速划动鱼会散开。
3. 点击水面 → 涟漪 + 鱼食下落 → 鱼游过去吃掉。
4. 1080p 高画质稳定 ≥ 55fps（RTX 3060 级），低画质 ≥ 30fps（核显）。
5. 线上 Demo 可访问，无控制台报错。
